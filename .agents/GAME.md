# Game identity

This file is the current creative contract, not an inventory of every object.
Store choices that future prompts should normally preserve: genre, core loop,
setting, tone, camera, art direction, and other defining gameplay constraints.
Keep implementation details in ARCHITECTURE.md and current bugs in CONTEXT.md.

## Maintaining identity

- When a prompt clearly establishes a choice, record the choice, its meaning, and
  its source day or direct owner decision. Leave undecided areas open.
- Mark temporary demos, experiments, and fallback visuals as provisional; building
  them does not automatically adopt them as the game's identity.
- Extend adopted choices by default. Changing one requires clear intent in the
  selected prompt or a direct owner decision. A request for a weapon does not
  implicitly replace the game's genre; an explicit request to replace turn-based
  combat with real-time combat can.
- On an authorized change, record the new choice and source here. Preserve the old
  choice and reason for replacement in that day's journal, linked from this file.
- Suggestions the agent wants to challenge remain labeled proposals until authorized.

Each adopted entry should state **choice**, **decision**, **reason**, and **origin**.
Use named entries that can be extended as the game develops; avoid empty placeholder rows.
